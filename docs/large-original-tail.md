# Larger original-text retention for the 1M subscription route

The 1M context / 900000 compaction threshold remain unchanged. Current live settings will retain 40–50 turns with a soft target of 100000 tokens after the next application compaction. Short history keeps all available turns; short turns can reach the 50-turn maximum without filling 100K. Long turns are not cut mid-message to force the token target. API routes retain their pre-existing 10–15 turn / 20K policy.

Harness configuration adds validated LUMI_HARNESS_TAIL_MIN_TURNS, LUMI_HARNESS_TAIL_MAX_TURNS and LUMI_HARNESS_TAIL_TARGET_TOKENS values. Defaults remain 10/15/20000 for deployments without these settings. The deployed subscription route sets 40/50/100000. The actual planner, old-boundary recovery and diagnostics use the same per-thread policy. /v1/chats/:id/runtime reports the policy in harness.contextPolicy; cache diagnostics report the active thread's actual retention policy.

Changing retention does not mark compactedAt, alter the active history boundary, open a Session, rewrite the persona or modify the cached prompt prefix. Session replacement remains limited to an actual completed application compaction, at the configured 900K threshold. All stored chat messages remain unchanged.

SDK transcripts can grow through autonomous/tool rounds even when visible conversation has fewer than the requested minimum turns. At the actual threshold, that case now distills the available conversation while retaining all its originals. The summary is allowed to overlap the raw tail; activeChatMessages honors the raw-tail boundary before excluding summarized messages, preventing an overlapping summary boundary from removing originals. This continues to use Lumi's existing emotional-summary rules and summary persistence/commit logic.

Tests include selection of complete 40–50 turns, API policy isolation, no compaction below 900K, overlapping boundary retention and excluded-message handling. The complete HTTP/scheduler/SDK fixture seeds 60 conversation rounds, reports a simulated 900K upstream input, completes application compaction and inspects the next primary SDK request: all 49 retained original rounds plus the latest trigger round are present verbatim, while the permanent archive still contains every original. A second fixture fills the SDK window with only eight visible rounds, verifies compaction can complete and confirms every visible original remains in the actual next request. The tests use local fake providers only.
