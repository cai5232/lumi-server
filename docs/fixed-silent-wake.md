# Fixed 18-minute optional-contact wake

The application owns the ordinary autonomous cadence: 18 minutes after the latest completed chat/wake. Model-proposed nextWakeMinutes and followUpMinutes no longer override it. Explicit reminders, scene triggers, sleep, stop controls, and foreground-request locks retain their separate behavior. Errors wait 18 minutes rather than rapidly retrying.

`prompts/wake-fixed-silent.md` is a delivery protocol loaded only for autonomous turns. It replaces the active mandatory-contact rule, while preserving the old Markdown files byte for byte and leaving the editable autonomous task/persona intact. The assistant may return `[[LUMI_SILENT_WAKE]]` or `sentinel_decision.action=none`. Delivery intent is captured before HTML/photo extraction. A silent turn does not append any assistant message, fallback greeting, HTML card, or chat push. Its internal activity event contains a generic quiet-wake description. Memory tags and authorized tools retain their original behavior.

For Claude Agent SDK (`kimi-harness`) wakes use the existing `thread:chat` Session, with the same thread-level foreground/background exclusion. No old transcript is deleted or migrated, and switching this routing does not rebuild the primary Session. The wake receipt is finalized against the unchanged visible archive even after silence. Subsequent chat and restart restore that Session. Application compaction is still the only reason to rebuild; wake token usage now also feeds the existing background compaction check and emotional-summary pipeline.

DND keeps the 18-minute inference cadence but limits delivery to none. Explicit sleep or disabled autonomous mode still stops ordinary wakes. Normal conversations postpone an idle wake to avoid redundant requests. Separate cache-keepalive probes remain disabled. An autonomous inference consumes the selected route's quota; cache TTL/hits remain provider-controlled and this does not guarantee one-hour retention. Native ACP retains its original separate scope; the deployed route is SDK.

Validation uses simulated providers and the pinned SDK against a localhost fixture, including silent/no-push persistence, repeat pulse, restored due time, normal messages, DND, foreground/sleep guards, failure interval, fixed settings HTTP response, SDK Session restart/resume, unchanged persona hashes, images/tools/memory and application compaction. No live model probes are needed for this change.
