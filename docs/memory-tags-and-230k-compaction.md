# 标签记忆与 230K 压缩

按用户要求，模型新增记忆只使用原有 `<memory>…</memory>` 隐藏标签，由 Lumi 在正常回复后调用原 Nocturne 写入接口。人格与原始 Markdown 文本、情感摘要、长期记忆和聊天记录均不改写。

Harness 的 Nocturne 工具默认只读，只注册 memory_search 和（原本支持时）memory_get。不注册 memory_write / memory_update，执行层也拒绝直接调用隐藏写入处理器。生产初始化不再向适配器传写入或更新函数。旧 nocturne-memory 外部 MCP 在持久配置中关闭，避免 hold 等别名成为另一条模型写入通道。自动检索仍直接调用原 API，与 MCP 开关独立；用户在前端主动管理记忆的接口继续保留。检索不会触发写入。

将运行配置的 Harness 上下文上限设为262144，压缩设置为230000。安全策略尊重设置的阈值，仅在超过模型安全空间时限幅，通常保留32000 tokens（小窗口按20%，且至少16000）给回复、工具和估算误差。旧代码无条件对输入预算乘0.8，导致设置200K时实际150400触发，现移除此隐式限制。当前配置实际阈值为230000，输入预算250144。Kimi官方模型说明核对了当前K2.8以及K3的窗口容量；保持当前模型ID、供应商和effort不变。

配置及工具变更继续恢复同一Session，只有应用层实际压缩换窗才会重建。最近10～15轮/约20K原文保留与情感摘要规则不变。模型调用失败仍不自动转其他付费线路。

验证：只读工具执行层防绕过；HTTP+模拟SDK中自动检索无写入、无记忆写入工具、标签只写一次且不出现在正文；模型窗口限幅/230K实际阈值；窗口和工具定义改变续用原Session；重启恢复、自动压缩、图片与画室、历史与原始Markdown保持。测试使用本地模拟模型，不消耗Kimi推理额度。
